# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Клиент: взрослый 30–55 лет, занятый и тревожный, который помогает вести здоровье пожилого родителя (или ребёнка, или своё). Работает в основном с телефона: заводит лекарства, смотрит, что принято сегодня, открывает сводку перед визитом к врачу.

Участники семейного круга по приглашению: брат, сестра, супруг, сиделка и сам человек, за которым ухаживают («Сам(а)»). Врачи, которым открыта сводка по временной ссылке.

Сотрудники сервиса работают за компьютером в `/staff/`: поддержка, запросы субъектов данных, внесение документов, если клиент передал их сервису.

## Product Purpose

Семья ведёт здоровье близкого сама, без посредников. Сценарий MVP: «заведите маму за 5 минут» — профиль, лекарства с расписанием, приглашение мамы или сиделки по ссылке, отметки приёма, на экране «Сегодня» владелец видит, что принято, а раз в неделю формируется сводка для врача. Рядом хранятся анализы, документы и замеры давления.

Успех MVP: не меньше 10 семей отмечают приёмы или пишут в дневник не реже 4 дней в неделю в течение 3 недель из первых 4.

## Positioning

Спокойный семейный журнал приёма лекарств и самочувствия с контролем доступа: каждое открытие данных записывается в журнал, который видит владелец; за каждого человека есть отдельное согласие. Это не лабораторное приложение и не сервис с живым помощником: семья делает всё сама, а сервис снимает бумажную возню и тревогу «приняла ли мама».

Тон: спокойный, без обещаний лечения и без оценок состояния.

## Operating Context

- Клиентское приложение (`/`): телефон — основное устройство, на компьютере удобная версия с боковым меню.
- Рабочее место сотрудников (`/staff/`): компьютер, обращения, документы на внесение, запросы субъектов данных.
- Документы: бланки лабораторий в фото и PDF, выписки, снимки, рецепты, прививки, полисы.
- Сводка для врача печатается на одном листе A4; ссылка для врача временная и открывается без входа.
- Данные хранятся на сервере (Node + SQLite), письма уходят через SMTP.

## Capabilities and Constraints

- Никаких диагнозов, прогнозов и советов по лечению: только факты (значение, диапазон лаборатории, изменение во времени). Отклонение — только относительно референса лаборатории, формулировка «вне диапазона лаборатории». У давления референса нет.
- Данные о здоровье — специальная категория. Согласия оформляются отдельными документами, подпись согласия на данные о здоровье — кодом на почту. Подтверждения за других людей, журнал доступа, отзыв и удаление данных уже есть.
- Роли: владелец, близкий («просмотр» или «просмотр и добавление»), сотрудник. Права проверяются на сервере.
- Распознавание бланков через Claude выключено по умолчанию, работает заглушка; включение требует отдельного согласия и юридической проверки (трансграничная передача).
- Юридические тексты — черновики до проверки юристом; реквизиты оператора не заполнены.
- Кнопка демо-данных в рабочей версии не нужна и удаляется.
- Open: платежи, регистрация в Роскомнадзоре, размещение на сервере в РФ, шифрование базы и файлов, двухфакторный вход.

## Care Stage

Вторая часть продукта — ежедневный уход: лекарства и отметки приёма, дневник дня, визиты к врачу, экстренная карточка. Пользуется ими не только ухаживающий родственник: человек, за которым ухаживают, участвует сам (приглашение «Сам(а)», простой режим) и не должен чувствовать надзора. Поэтому нет оценок, нет «пропущен», нет красных тревог, а уведомления по умолчанию получает только владелец.

## Brand Commitments

- Название: «Близкие».
- Из исходного брифа пользователя: спокойный и вызывающий доверие стиль, много воздуха, мягкие нейтральные цвета, один акцентный цвет; «медицинского» красного нет, красный только для отклонений; крупный читаемый шрифт, понятные подписи, никаких медицинских сокращений без расшифровки.
- Во всех экранах клиента в подвале: «Сервис не заменяет консультацию врача».
- Слово «прототип» из интерфейса убрано по решению пользователя.

## Evidence on Hand

Нет реальных клиентов, отзывов и метрик; их выдумывать нельзя. Реальных медицинских данных в репозитории нет. Учётные записи сотрудников создаются случайно при первом запуске.

## Product Principles

1. Спокойствие вместо тревоги: тон и оформление не пугают, красный только там, где значение вне диапазона лаборатории.
2. Простые шаги: интерфейс всегда показывает, что сделано и что ждёт, без лишних действий.
3. Контроль у владельца: кто видел, кто имеет доступ, что отозвано, всё видно и обратимо.
4. Только факты: ни оценок, ни диагнозов, ни рекомендаций, ни выдуманных обещаний.
5. Сначала телефон для клиента, компьютер для сотрудников.

## Accessibility & Inclusion

Аудитория включает людей 55+ (сиделки, пожилые близкие): крупный читаемый шрифт, достаточный контраст, большие области нажатия, русский язык без профессионального жаргона.

## Later (после MVP)

- Консьерж: платный тариф с живым помощником по здоровью (внесение документов, поручения, запросы в клиниках, ответы в течение рабочего дня). Код и рабочее место сотрудников для него уже есть, но на главном экране и в позиционировании MVP консьерж не упоминается.
- Платежи, приложение для телефона, push, SMS и Telegram, распознавание документов, интеграции с клиниками.
