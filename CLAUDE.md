# Близкие

Личный помощник по здоровью семьи. Клиент ведёт семейное досье (анализы, документы, замеры), приглашает близких и общается с помощником. Сотрудники работают в отдельном приложении (`/staff/`). Интерфейс и тексты — на русском. Контекст продукта: [PRODUCT.md](PRODUCT.md), визуальная система: [DESIGN.md](DESIGN.md).

Юридические тексты в `src/legal/` — черновики до проверки юристом; до этого реальные данные не принимать.

## Команды

Нужен Node.js 22.5 или новее (используется встроенный `node:sqlite`).

```bash
npm install
npm run server   # API и хранилище, http://127.0.0.1:3000 (читает .env)
npm run dev      # Vite: клиенты на :5173, сотрудники на :5173/staff/
npm run build    # сборка обоих приложений в dist/
npm start        # сборка и запуск одним сервером на :3000 (NODE_ENV=production)
npm run backup   # резервная копия базы
```

Смоук-тест: `npm test` (поднимает сервер на временной базе и проходит основные сценарии, в том числе уход и права). Проверяйте также сборкой (`npx vite build`) и в браузере на ширине 375 px.

## Структура

- `server/` — Express и SQLite без внешних сервисов. Файлы — `server/data/uploads`.
  - `index.js` — маршруты, права, шлюз согласий (`gate`).
  - `state.js` — сборка состояния семьи с учётом прав (`buildState`), `consentOk`.
  - `consent.js` — согласия, подпись кодом, запросы субъектов, выгрузка, удаление.
  - `account.js` — восстановление пароля, смена пароля, команда сотрудников. `mailer.js` — письма через SMTP (без SMTP пишет в `outbox.log`).
  - `recognize.js`, `prompts.js` — распознавание бланков через Claude (выключено по умолчанию).
  - `care.js` — лекарства, отметки приёма, дневник, визиты, уведомления, экстренная карточка. `scheduler.js` — планировщик раз в минуту (идемпотентный, `SCHEDULER=0` отключает), `notify.js` — уведомления и письма, `timeutil.js` — время семьи (`families.timezone`).
  - `db.js` — схема и миграции (`addColumn`), `seed.js` — аккаунты сотрудников.
- `src/` — клиентское приложение (React, Tailwind 4, Recharts, хэш-маршрутизация).
  - `lib/store.js` — состояние из API. Экраны читают один объект `state`, действия — `actions.*`.
  - `lib/indicators.js` — справочник показателей, единицы, пересчёт. `lib/data.js` — выборки для графиков.
  - `lib/recognize.js` — единственная точка распознавания через ИИ (по умолчанию выключено: показатели вносит человек). `lib/draft.js` — черновик анализа в форме.
  - `legal/` — юридические документы и реквизиты оператора.
  - `components/` — оболочка (`Layout`), примитивы (`ui.jsx`), иконки (`icons.jsx`), форма анализа (`ResultForm.jsx`).
  - `screens/` — экраны клиента, `staff/` — приложение сотрудников (`/staff/`, свой вход, администратор видит «Команда»).
- `docs/legal/RESEARCH.md` — правовая карта с источниками и открытыми вопросами.

## Роли и права

Владелец (`owner`), близкие (`add` — просмотр и добавление, `view` — только просмотр), сотрудник (`staff`). Близкие не видят переписку, поручения и журнал. Права проверяются на сервере; кнопки в интерфейсе скрываются только для удобства.

## Правила, которые нельзя нарушать

**Уход (лекарства, дневник, визиты)**
- Не оценивать и не советовать: никаких «опасно», «плохая приверженность», советов по дозам и сочетаниям. Неотмеченный приём называется «не отмечен», а не «пропущен».
- В письмах и темах писем нет сведений о здоровье (названий лекарств, текста дневника, диагнозов): только факт события и ссылка.
- Кто отметил (`marked_by_self`, `by_self`), выставляет сервер по `grants.self_profile_id`, а не клиент. Пользователь «Сам(а)» видит только свой профиль и журнал просмотров своего профиля, без переписки, поручений и «Круга заботы».
- Публичная экстренная карточка собирается отдельной функцией в `server/care.js` и отдаёт только поля карточки. Не добавляйте туда данные из `buildState`.
- Планировщик идемпотентен через `UNIQUE` и метки времени; не создавайте уведомления без `ref_id`.

**Тексты продукта**
- Никаких диагнозов, прогнозов и советов по лечению. Только факты: значение, диапазон лаборатории, изменение во времени.
- Отклонение подсвечивается только относительно референса лаборатории, формулировка «вне диапазона лаборатории». Слов «болезнь», «опасно», «норма/не норма» быть не должно. У давления нет референса лаборатории, поэтому его не оценивают.
- В подвале каждого экрана — «Сервис не заменяет консультацию врача».
- Без медицинских сокращений без расшифровки.

**Данные и согласия (152-ФЗ, 323-ФЗ)**
- Данные о здоровье — специальная категория. Запись данных на сервере блокируется, пока владелец не подписал согласие `consent_health` кодом (`consentOk`). Не обходите `gate` в новых маршрутах записи.
- Каждое согласие — отдельный документ, а не часть соглашения или политики. Галочки не предзаполняются.
- Профиль не-владельца создаётся только с основанием (`basis`) и подтверждением. Несовершеннолетним данные вносит законный представитель.
- Доступ близкому и ссылка врачу требуют подтверждения согласия; события пишутся в журнал, который видит владелец. Открытие данных сотрудником тоже пишется.
- Отзыв согласия останавливает обработку, удаление через 30 дней. Новые таблицы с персональными данными нужно учитывать в `wipeFamily`, выгрузке и удалении аккаунта.
- Версии текстов документов лежат в `src/legal/docs.js`; при изменении текста обновляйте `LEGAL_VERSION`. Хеш текста записывается вместе с согласием.
- Тексты документов — черновики, их проверяет юрист. Реквизиты в квадратных скобках не заполнять выдуманными значениями.
- Распознавание через ИИ отправляет данные за границу. Не включать по умолчанию и не отправлять без согласия `consent_ai` на каждую отправку.

**Безопасность**
- Пароли только в виде scrypt-хеша. Сессия в HttpOnly-cookie. Изменяющие запросы требуют заголовок `x-app: 1` (клиент делает это через `src/lib/api.js`).
- Загрузка файлов: только JPG, PNG, WebP, HEIC, PDF, до 25 МБ, проверка типа и сигнатуры PDF. Файлы отдаются с `nosniff` и ограничивающим CSP.
- Ответ модели считается недоверенным: проходит `sanitize` в `server/recognize.js`.
- Не коммитьте `server/data/` (база, файлы, `staff-credentials.txt`, `outbox.log`), ключи и пароли. Тестовые учётные записи генерируются случайно при первом запуске.
- Коды подтверждения уходят письмом (SMTP в `.env`). Только без SMTP и вне production код показывается на экране для проверки. Секреты (`.env`) в git не попадают.

## Соглашения по коду

- Простой JavaScript и JSX, без TypeScript. Стиль соседних файлов: без точек с запятой, одинарные кавычки, двойные пробелы.
- Первый экран — телефон шириной 375 px. Никакого горизонтального прокручивания. Кнопки не ниже 48 px.
- Сводка для врача печатается на одном листе A4: класс `no-print` скрывает лишнее, для проверки печати используйте Chrome `--print-to-pdf` и число страниц.
- Данные сервера приходят в camelCase, в базе snake_case; преобразование в `server/state.js`.
- Новые поля `Measurement` нормализуются на клиенте (`normalizeRow`), сервер хранит и исходные, и приведённые значения.
- Оформление: токены в `src/index.css` (`@theme`), шрифт Onest (self-hosted), иконки только из `icons.jsx`, полоса диапазона `RangeBar` для значений относительно лаборатории, hairline-списки вместо карточек, один акцент (зелёный), основная кнопка зелёная, чёрного цвета нет, иконки Phosphor. Красный только для значений вне диапазона лаборатории и ошибок. Без вложенных карточек, эйбрау над заголовками и градиентного текста.
- Маршруты клиента — хэш (`#/dossier`, `#/indicator/hgb`, `#/today`, `#/meds/<pid>`, `#/visits/<pid>`, `#/care/<pid>/new`, `#/emergency/<pid>`). Публичные страницы без входа: `#/invite/…`, `#/share/…`, `#/consent/…`, `#/legal/…`, `#/sos/<token>`.

## Особенности окружения

- Node.js установлен через Homebrew: `export PATH=/opt/homebrew/bin:$PATH` перед `npm`/`node` в новых оболочках.
- Для HMR и API нужны оба процесса: `npm run server` и `npm run dev` (Vite проксирует `/api` на :3000).
- Сброс данных разработки: остановить сервер и удалить `server/data/`.
