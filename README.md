# Близкие (Kin) — прототип

Личный помощник по здоровью семьи. Клиент ведёт семейное досье (анализы, документы, замеры), приглашает близких и общается с помощником; сотрудники работают в отдельном приложении.

**Прототип. Не загружайте реальные медицинские документы.** Данные хранятся в файлах на сервере разработки.

## Запуск

Нужен Node.js 22.5 или новее.

```bash
npm install
npm run server      # API и хранилище, http://127.0.0.1:3000
npm run dev         # интерфейс, http://localhost:5173 (клиенты) и http://localhost:5173/staff/ (сотрудники)
```

Или одним сервером на собранном приложении: `npm start` (сборка и запуск на :3000).

При первом запуске сервер создаёт две учётные записи сотрудников со случайными паролями и записывает их в `server/data/staff-credentials.txt` (файл не попадает в git). Клиенты регистрируются сами на главной странице.

## Что есть

**Клиентское приложение (`/`)**
- Регистрация и вход, у каждой семьи свой помощник.
- Профили, анализы (распознавание — заглушка с проверкой человеком), замеры, динамика, сводка для врача на одну страницу A4.
- **Помощник**: поручения со статусами и переписка с сотрудником.
- **Досье**: все документы, загрузка фото и PDF на сервер, отправка бланка помощнику на внесение.
- **Круг заботы**: приглашение близких по одноразовой ссылке, права «просмотр» или «просмотр и добавление», срок доступа, выбор профилей, закрытие доступа, журнал просмотров, временная ссылка для врача.

**Рабочее место сотрудников (`/staff/`)**
- Входящие: очередь диалогов, непрочитанные, фильтры «Ждут ответа» и «Мои», поиск, ответственный, шаблоны ответов, внутренние заметки (клиент их не видит).
- Поручения: доска «Принято / В работе / Готово» с назначением.
- Документы: очередь, просмотр бланка рядом с формой, внесение показателей, уведомление клиента.
- Каждое открытие данных семьи сотрудником попадает в журнал клиента.

## Устройство

- `server/` — Express и встроенный SQLite (`node:sqlite`), без внешних сервисов. Файлы лежат в `server/data/uploads`.
- Права: владелец, «просмотр», «просмотр и добавление», сотрудник; близкие не видят переписку и поручения.
- Пароли хранятся как scrypt-хеш, сессия в HttpOnly-cookie, изменяющие запросы требуют заголовок `x-app`, на вход действует ограничение числа попыток.
- `src/lib/recognize.js` — единственная точка распознавания; сейчас заглушка.
- Отклонения подсвечиваются только относительно референса лаборатории; диагнозов, прогнозов и советов нет.

## Что ещё нужно до реальных данных

Письма и уведомления, шифрование файлов и базы, резервные копии, двухфакторный вход, восстановление пароля, юридическая проработка обработки данных о здоровье (152-ФЗ), размещение на сервере в РФ.
