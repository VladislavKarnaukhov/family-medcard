# Близкие (KIN)

Личный помощник по здоровью семьи. Клиент ведёт семейное досье (анализы, документы, замеры давления), видит динамику показателей, приглашает близких и общается с помощником. Сотрудники работают в отдельном приложении: очередь диалогов, внесение показателей из бланков, поручения.

Два приложения на одном сервере:

- **Клиенты** — `/` (телефон в первую очередь, на компьютере боковое меню);
- **Сотрудники** — `/staff/` (компьютер, три панели).

## Запуск

Нужен Node.js 22.5 или новее.

```bash
npm install
cp .env.example .env     # заполните почту, см. ниже
npm run server           # API и хранилище, http://127.0.0.1:3000
npm run dev              # интерфейс для разработки, http://localhost:5173 и http://localhost:5173/staff/
```

Показать сайт другим людям без сервера и карты: `npm run share`. Скрипт собирает приложение, запускает сервер и открывает его в интернет через бесплатный туннель Cloudflare (нужно один раз `brew install cloudflared`). Он напечатает адрес вида `https://….trycloudflare.com`; адрес меняется при каждом запуске, а сайт работает, пока команда запущена. Без туннеля: `npm run share -- --no-tunnel`. Для тестовых данных.

Рабочий запуск одним процессом: `npm start` (сборка и сервер на :3000 с `NODE_ENV=production`).

При первом запуске сервер создаёт учётные записи сотрудников со случайными паролями и записывает их в `server/data/staff-credentials.txt` (файл не попадает в git). Первый сотрудник — администратор: в разделе «Команда» он добавляет остальных, они получают письмо со ссылкой для пароля. Чтобы сразу создать настоящего администратора, задайте `ADMIN_EMAIL` (и `ADMIN_NAME`) до первого запуска. Клиенты регистрируются сами.

## Настройка (`.env`)

| Переменная | Назначение |
|---|---|
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` | Отправка писем: коды подписи согласий, приглашения, восстановление пароля, уведомление о новом сообщении помощника (без текста сообщения). |
| `MAIL_FROM` | Адрес отправителя; он должен быть подтверждён у почтового провайдера. |
| `APP_URL` | Публичный адрес приложения для ссылок в письмах. |
| `NODE_ENV=production` | Secure-cookie, строгие заголовки (CSP, HSTS), коды подтверждения не показываются на экране. |
| `TRUST_PROXY=1` | Если сервер стоит за обратным прокси (нужен корректный IP и HTTPS). |
| `ANTHROPIC_API_KEY`, `AI_RECOGNITION=1` | Распознавание бланков через Claude (по умолчанию выключено, см. ниже). |

Без SMTP письма не уходят: они пишутся в `server/data/outbox.log`, а вне production код подписи показывается на экране, чтобы можно было проверить поток.

Резервная копия: `npm run backup` (база), папку `server/data/uploads` копируйте отдельно.

## Что умеет

**Клиент**
- Регистрация и вход, восстановление пароля, смена имени и пароля.
- Профили (свой, мамы, ребёнка), лента-история, показатели с графиками и данными разных лабораторий на одном графике, пересчёт единиц, замеры давления, сводка для врача на одну страницу A4.
- Анализы: загрузка фото или PDF, внесение самому рядом с бланком или отправка помощнику; исправление сохранённых анализов.
- Помощник: переписка, поручения со статусами, уведомление по почте.
- Досье: все документы по типам, файлы на сервере.
- Круг заботы: приглашения по ссылке или письмом, права, срок, выбор профилей, журнал просмотров, временная ссылка для врача.
- Мои данные и согласия: реестр согласий, запрос по персональным данным, выгрузка, отзыв согласия, удаление аккаунта.

**Сотрудники**
- Входящие: очередь диалогов, «ждут ответа», «мои», поиск, ответственный, шаблоны ответов, внутренние заметки (клиент их не видит).
- Справка о клиенте рядом с перепиской: профили, поручения, документы.
- Документы: очередь, бланк рядом с таблицей, внесение показателей, уведомление клиента.
- Поручения: доска «Принято / В работе / Готово».
- Запросы субъектов данных со сроками ответа; команда (для администратора).
- Каждое открытие данных семьи сотрудником записывается в журнал клиента.

Без распознавания через ИИ показатели вносит человек: клиент сам или помощник. Если включить распознавание (`server/prompts.js`, `server/recognize.js`), бланк уходит стороннему сервису за границу; это трансграничная передача данных о здоровье (ст. 12 152-ФЗ), нужны отдельное согласие на каждую отправку (`consent_ai`, уже в интерфейсе), реквизиты в `src/legal/operator.js`, уведомление Роскомнадзора и юридическая проверка.

## Правовой слой

- Тексты документов (соглашение, политика, отдельные согласия, шаблон полномочия для клиник) — `src/legal/docs.js`; реквизиты оператора — `src/legal/operator.js`. Это **черновики**, их должен проверить юрист, реквизиты в квадратных скобках нужно заполнить.
- Правовая карта с источниками и открытыми вопросами — [docs/legal/RESEARCH.md](docs/legal/RESEARCH.md).
- В продукте: раздельные согласия при регистрации, подпись согласия на данные о здоровье кодом, подтверждения за других людей, подтверждения при доступе близким и ссылке врачу, реестр согласий, отзыв, выгрузка, удаление, очередь запросов субъектов.

## Устройство

- `server/` — Express и встроенный SQLite (`node:sqlite`), без внешних сервисов. Файлы лежат в `server/data/uploads`.
- Права: владелец, «просмотр», «просмотр и добавление», сотрудник, администратор; близкие не видят переписку и поручения.
- Пароли — scrypt, сессия в HttpOnly-cookie, изменяющие запросы требуют заголовок `x-app`, ограничение числа попыток входа, регистрации и запросов.
- Оформление: спокойная «выписка» (белые строки на тёплой бумаге, один зелёный акцент, полоса диапазона для каждого значения), шрифт Onest, иконки Phosphor. Описание системы — [DESIGN.md](DESIGN.md).

## Что ещё нужно до реальных данных

Шифрование базы и файлов, двухфакторный вход, размещение на сервере в РФ, регистрация в Роскомнадзоре, юридическая проработка (152-ФЗ, врачебная тайна), подтверждение адреса отправителя у почтового провайдера, мониторинг и регулярные резервные копии.
